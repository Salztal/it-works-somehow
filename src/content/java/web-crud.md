# 10. Webでも一覧・更新・削除する

## ゴール

一覧から対象を選び、現在値の確認、更新、削除の取り消しと実行ができます。DB処理はコンソール版の知識を使います。

## 思い出す

1. DBから複数行を受け取る型は何ですか。
2. 存在しないIDの1件取得は何を返しますか。
3. DBを変更するHTTPメソッドは、GETとPOSTのどちらですか。

答えは`List<TaskDto>`、null、POSTです。

## 開始コード

[第10章開始ZIP](assets/downloads/10-web-crud-start.zip)を使います。Web版DAOの`selectAll`、`updateTask`、`deleteTask`が未実装です。ServletとJSPは用意済みです。第6・7章を参考に、同じ役割のメソッドを実装します。パッケージ名が`com.todojsp`で始まる点を確認しましょう。

## 1. 一覧へ渡す値を読む

`ViewServlet.doGet`の次の処理を探します。

```java
request.setAttribute("tasks", new TaskService().findAll());
```

`tasks`という名前でJSPへListを渡しています。JSP側の`c:forEach`が1件ずつ取り出します。

```jsp
<c:forEach var="task" items="${tasks}">
    <c:out value="${task.title}"/>
</c:forEach>
```

DAOのループはDBの行をDTOへ変換する処理、JSPのループはDTOを画面へ表示する処理です。それぞれの場所で違う仕事をしています。

## 2. 更新の2段階を読む

```text
GET /update?id=123 → 対象を取得 → 現在値入りフォーム
POST /update      → 入力チェック → 更新 → GET /view
```

IDは例です。実際の一覧で表示されたIDを使います。GETで対象を探し、POSTで更新します。hiddenフィールドのIDも利用者が変更できる入力として扱い、サーバーで形式と対象の有無を確認します。

## 小課題：DAOを完成させる

1. `selectAll`を第6章と同じ手順で実装する。
2. `updateTask`に4つのパラメータを設定する。
3. `deleteTask`に1つのIDを設定する。
4. ServletやJSPのSQLを書き足さず、DAOに閉じ込める。

### ヒント1

この演習で新しくSQLを設計し直す必要はありません。コンソール版との違いは、呼び出す入口と表示です。

### ヒント2

戻り値もコンソール版と同じです。一覧はList、更新・削除は件数です。[第6章](console-list.md)と[第7章](console-edit.md)を参照できます。

## 動作確認の順序

| 操作 | 期待する結果 |
|---|---|
| 一覧を開く | DBの行がID昇順で表示される |
| 更新リンクを押す | 選んだタスクの現在値が出る |
| 詳細を消して完了へ更新 | その1件だけが変わる |
| 同じ値で再更新 | 対象ありとして扱う |
| 削除リンクを押す | 確認だけ。まだ消えない |
| 取り消す | 一覧へ戻り、行が残る |
| 削除を実行する | 対象の1件だけ消える |
| 存在しないIDを指定 | 対象なしの案内になる |
| IDに文字や0を指定 | 入力の案内になる |

一覧が0件になった場合は「タスクはありません」と表示します。DB接続の失敗は0件と混同せず、エラーを表示します。

## 完成条件

コンソール版で保存した内容をWebで編集し、その結果をコンソールの一覧で確認できます。削除のGETだけではDBを変更しません。

## 最後に説明する

Web版を作るために新しくなった部分と、コンソール版から考え方を引き継いだ部分を、各クラスを指して説明してください。
