# Phase 4 Git：調査と設計

調査日：2026-11-11。対象は既存 Astro / TypeScript の technical-notes。既存URL、移行原稿、v1保存形式・technical-notes:v1:<base>は維持する。Commit・Push・公開・作者設定変更は実施しない。

## 統合箇所

- catalog.ts の既存 Entry に Git の15講義・5ミッションを追加。共通ルーター・目次・前後移動・完了・問題回答・メモを再利用。
- Securityと同じprepare方式でgit-catalog.jsonを生成し、全ページ共通のクライアントへ教材本文・全解説を含めない。
- search.json に講義本文、ミッション、状況別QAを含める。QAは状況名で検索し、該当詳細へ移動。
- /git/ は目的別入口と5 Unitの講義目次。/git/rescue/ は状態別の分岐、/git/lab/ はブラウザ内限定演習、/git/comparisons/ は操作前後の比較。
- 保存スキーマは変更せずキー git:g01 等を追加。既存問題IDは変更しない。シミュレーターはメモリー内で動作し学習記録の削除APIを持たない。
- 共通の色・カード・読書レイアウト・コピー機能を利用。横長グラフは領域内スクロールと親一覧を併設。入力はネイティブのbutton/select/radioを利用。

## 内容の順序

各講義は困る状況→状態確認→目的と判断→操作→結果→失敗時→補足→問題→出典。専門用語は必要な時点で説明。LUNATICは設けない。

事故対応はstatus/diff/log、保全、公開範囲の判定、対処、検証・報告の順。未記録データの復旧を保証しない。認証情報は失効・ローテーションを優先。

## 限定モデル

テキストファイル単位のスナップショット、単一作業ツリー、通常コミットを扱う。複雑な行マージ、rename、バイナリ、サブモジュール、署名、ネットワーク、実リポジトリは対象外。同一ファイルの両側変更は保守的に競合として止める。競合は編集内容の明示選択・ステージ・続行、または中断。実Gitで同じ限定ケースを照合する。
