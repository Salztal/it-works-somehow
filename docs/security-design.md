# Phase 2 Security 調査・設計

調査日: 2026-11-11。対象: 既存 `Salztal/it-works-somehow` のローカル checkout `technical-notes`。Push・公開は対象外。

## 既存構造と互換性

- Astro 7 / TypeScript / 静的出力。`catalog.ts` の教材とカテゴリを `[...slug].astro` が列挙する。NetworkはJSON、JavaはMarkdownと生成処理。原本とZIPは既存ハッシュ検査を継続する。
- `Shell.astro`、EntryList、既存CSS、採点処理、学習記録を再利用。Security本文だけ構造化JSONと専用表示部品を追加する。
- 記録は `technical-notes:v1:${BASE_URL}`。version=1、completed/answers/recall/notes/lastを維持。Securityは `security:s01-01`、回答は `s01-01:0` 等の衝突しない追加キー。既存記録の変換も保存領域の変更も不要。検証関数を純粋関数に分離し旧形式の往復を検査する。
- 既存 `href()` を全内部リンクに使用。`/security/{basics,advanced,lunatic}/sNN-NN/`。元URLは変更しない。
- 検索は既存 `search.json` に本文・問題・参考資料を追加。既存27文書を削除しない。

## 教材設計

各ユニット3レッスン、01〜06 BASIC=18、07〜09 ADVANCED=9、10 LUNATIC=3。難易度は内容の深さであり試験出題比率ではない。BASICはCIA/リスク→攻撃→Web/通信→暗号→認証/認可→対策/運用。ADVANCEDはTLS/PKI、認証基盤/メール、脆弱性/調査。LUNATICはTLS観測、DNSSEC検証、PQCの構造と限界。

JSONの各レッスンにID、番号、ユニット、難易度、前提知識、到達目標、複数の本文節、図解フローまたは比較表、具体例、誤解、3問以上（全選択肢の理由）、関連キー、一次資料の書誌情報（名称/発行元/URL/版または年月/確認日）を保持。生HTMLを入力せずAstroでエスケープ。問題は独自制作。

参照範囲はFE Ver.9.2、SC Ver.2.1・追補Ver.4.0を照合する。2027年度新制度案は未確定の参考資料として別扱い。IPA非公式・個人学習用と明記する。仕様の後継/廃止をRFC Editorや発行元で確認し、単なる古いRFC番号の再利用を避ける。観測年と発行年の違う統計は混同せず、原則架空事例を使う。

## 操作教材と安全性

ブラウザ内AES-GCM、SHA-256比較、ECDSA署名検証、TLSメッセージ選択、証明書チェーン、FWの先頭一致、メール認証alignment、架空ログ、脆弱性優先度、DNSSEC信頼チェーンを用意。鍵はメモリ上だけに保持。入力の上限、非対応環境、改ざん検証失敗、再初期化を扱う。外部通信・実環境攻撃を必要としない。教育用であり運用の暗号/認証基盤を代替しない。

TLS実験は合成PCAPと明示した静的サンプルを使う。暗号化されたTLSレコードを平文ハンドシェイクとして偽装しない。復号に必要なセッション秘密と証明書秘密鍵を区別する。

## 実装リスクと検査方針

- 進捗破壊: schema/storage keyを保持し旧バックアップと新キーの往復をテスト。
- 内容の陳腐化: 各出典に確認日を保持、仕様更新状況を記録。草案を確定規格として扱わない。
- 誤採点: 選択肢をシャッフルしても元indexを維持。全90問の範囲・理由・正答を機械検査し、純粋な判定関数と操作教材ロジックをテスト。
- 回帰: 元教材ハッシュ、Java ZIP、既存リンク/アンカー/検索索引検査を維持。
- Pages: rootとサブパスのビルド、全内部参照とHTTP配信を検査。ローカルでPC/モバイルと保存・検索を実操作確認。未実施は検証記録で区別。
- 公開物: 既存秘密情報パターンと不要ファイル検査を拡張せず維持。依存追加は原則不要。CIに同じSecurityチェックを組み込む。
