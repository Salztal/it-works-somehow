## 実装結果

5 Unit・15講義、各3問で45問。実践ミッション5件、各3問で15問。合計60問・240選択肢の個別解説。8操作教材、12注入障害、15症例の診断センター、16比較、34用語を追加した。全項目に関連講義・資料への導線を設け、本文・ラボ・症例・比較・用語を検索に収録した。

配送追跡、SMTP、DNS/MX、Postfixキュー、IMAP、送信ドメイン認証、TLS、ヘッダー/ログの8ラボは前提、入力と操作、前後の状態、理由、限界、不正操作、リセットを備える。外部通信や実メール送信を行わない。DKIMの実暗号検証はせず、署名検証結果を入力条件として与える。

全体の静的生成は285ページ（Mail追加40ページ）、検索文書336件（Mail追加93件）。Javaの11 ZIP・264エントリを保持する。

初回のHTTP照合はsandboxのloopback接続EACCESで停止した。ローカルHTTP検査に必要な権限で同じcheck-baseを再実行して成功した。実Gitの初回も一時リポジトリの`.git/config`書込み拒否で停止。その後、ユーザーの公開承認を受けて通常の完全verifyを権限付きで再実行した。作業リポジトリや永続設定を使ってテスト用の履歴を作らない。

Commit禁止の範囲でも検査できるよう、`verify --skip-real-git`を追加した。このオプションでも既存Gitの教材・モデル回帰は行い、専用一時リポジトリ内にテスト用Commitを作る既存の実Git照合だけを省略する。通常のverify/CIは従来どおり実Git照合も行う。

## 資料・モデルの限界

[一次資料と版・確認方法](mail-phase8-sources.md)、[調査と設計](mail-phase8-design.md)を参照。DMARCはRFC 9989、集計はRFC 9990、失敗レポートはRFC 9991。旧7489との探索・タグ・適用上の差を説明した。Postfix資料は公式検索索引での照合、DovecotはCE 2.4.5、Gmailは確認日時点の継続更新資料。

1通・1宛先、24h刻み・72h期限、固定DNS、確定済み組織境界を使う。実DNS Tree Walk、全SPF構文・参照制限、複数DKIM署名、ARC、実鍵、実TLS、実IMAP/POP3、製品の全キュー挙動は再現しない。全ラボと資料ページに明記する。

実SMTP送信、外部SMTP/IMAP/POP3認証、アカウント・認証情報の取得、DNS変更、Postfix/Dovecot起動、Docker/VM、実メール本文・ログ収集、既存サーバー変更は全て未実施。Foil Travelと他プロジェクトは変更していない。教材の検査成功は実メール基盤や到達率の保証ではない。
